# CodeAtlas 项目文档索引

> 本目录按**产品全生命周期**组织。每个阶段的产出物归档到对应文件夹，形成项目统一上下文。

## 一、目录结构

```
docs/
├── README.md              文档索引与归档规范（本文件）
├── 01-需求分析/           需求规划、PRD、需求池、竞品调研
├── 02-设计/               架构设计、接口契约、JSON Schema、交互稿
├── 03-开发/               技术方案、研发任务拆解、进度纪要
├── 04-测试/               测试用例、Bug 记录、验收清单
├── 05-评审/               评审材料、评审议题、评审结论
└── 06-上线复盘/           上线报告、数据观察、复盘结论与后续行动项
```

## 二、归档规则

| 阶段 | 归档内容 | 命名建议 |
| --- | --- | --- |
| 01-需求分析 | 需求文档（PRD）、需求池、优先级清单、待确认问题 | `需求文档-<主题>.md` |
| 02-设计 | 架构/技术设计、数据模型、接口契约（JSON Schema） | `设计-<主题>.md`；契约放 `schemas/` |
| 03-开发 | 技术方案、任务拆解、接口联调记录 | `方案-<主题>.md` |
| 04-测试 | 测试用例、Bug 清单、验收清单 | `用例-<主题>.md` |
| 05-评审 | 评审材料、议题清单、结论与待办 | `评审-<主题>-<日期>.md` |
| 06-上线复盘 | 上线总结、效果数据、后续优化项 | `复盘-<主题>-<日期>.md` |

## 四、归档决策准则

1. **一份文档只归属一个主阶段** —— 以「产出它的动作」为准，而非「它被谁阅读」。需求文档给测试同学看，仍归档在 `01-需求分析`。
2. **评审结论不覆盖原文档** —— 评审产出独立归档到 `05-评审`，原文档通过版本号（v0.2 → v0.3）演进，保留可追溯的决策链。
3. **契约随设计走** —— JSON Schema 这类跨阶段复用的契约，仍归 `02-设计`，因为它们是设计阶段的产物；其他阶段只**引用**，不复制。
4. **文档带版本号与状态** —— 每份主文档头部标注版本、状态（待评审/已评审/已冻结）、负责人，便于判断可用性。
