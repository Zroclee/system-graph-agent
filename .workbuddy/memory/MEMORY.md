## 核心设计准则

1. 代码能"证明"的绝不给 LLM；只能"猜"的给 LLM 但限定候选集内；都不行的交给人
2. LLM 只提议不落库，过四道闸门（Schema / 证据回验 / 置信度上限 / 冲突消解）
3. ID 内容寻址；缓存键必须含「依赖契约面哈希」，否则后端改签名前端静默命中缓存
4. 拿不准就升级全量——宁可慢一次，不要错一版
5. 范围守卫单点收口（ScopedFs），阶段代码物理上拿不到 `fs`
6. 写不出 fallback 的 LLM 任务不该存在（编译期强制）
7. 变更即确认失效：模块重跑后状态回退 `pending`
8. 任何未落盘的知识都视为已丢失（模块为检查点，原子写）

完整版见 `docs/02-设计/设计-架构方案.md` 附录 A。

## 用户工作习惯（项目内）

- **先讨论方案再落文档**：重要设计先口头对齐，确认后才写文件

- 偏好结构化产出 + 「决策准则」式清单；喜欢带示意图的说明
